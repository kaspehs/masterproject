# Training Config Reference

This directory contains YAML configs for the correction models and the standalone
force model. The public key names follow the thesis terminology. Older key names
are still accepted as aliases by `training.training_utils.parse_config`, but new
configs should use the names below.

Relevant thesis anchors:

- `sec:mf-framework`: force, frequency, and combined correction strategies
- `sec:network_inputs_nondimensionalization`: model inputs and scaling
- `sec:bounded_correction_outputs`: force and frequency output bounds
- `sec:downsampling`: trajectory downsampling
- `sec:losses`: one-step, multi-step, amplitude, spectral, and regularization losses
- `sec:nomf_implementation`: standalone latent-state force model

## Config Files

- `correction_smoke.yml`: quick CPU-oriented check for the VIVANA-TD correction trainer.
- `standalone_smoke.yml`: quick CPU-oriented check for the standalone force trainer.
- `final_configs/force_correction_model.yml`: selected force correction setup.
- `final_configs/frequency_correction_model.yml`: selected frequency correction setup.
- `final_configs/combined_correction_model.yml`: selected combined correction setup.
- `final_configs/standalone_model.yml`: selected standalone force-model setup.

## Core Sections

`method`
: Selects the trainer. Use `correction` for VIVANA-TD-based correction models and
`standalone` for the latent-state force model.

`data.dataset_root`
: Directory containing the prepared training dataset. The loaders expect the
final dataset layout generated by the VIVANA CFD data pipeline.

`data.downsample`, `data.downsample_factor`
: Enables temporal downsampling and selects the stride. The thesis uses a factor
of `20` as the practical training compromise discussed in `sec:downsampling`.

`model.fluid_density`, `model.diameter`
: Physical scales used for non-dimensionalization and force scaling. Current
rigid-cylinder configs use normalized values of `1.0`.

`model.input_scaling_basis`
: `structural_frequency` uses the structural natural frequency for velocity,
momentum, and acceleration scaling. `convective` uses flow-based scaling.

`model.reduced_velocity_scale`
: Divisor applied to reduced velocity when using structural-frequency scaling.
The thesis configs use `10.0`.

## Correction Models

`model.correction_strategy`
: `force` predicts an additive force-coefficient correction. `frequency`
predicts a correction to the VIVANA-TD non-dimensional excitation frequency.
`combined` predicts both.

`model.td_force_input_source`
: Optional baseline-force input to the network. Use `none`, `total`, or `fcv`.
This corresponds to the optional baseline TD force input in
`sec:network_inputs_nondimensionalization`.

`model.phase_input_source`
: Optional phase input. Use `none`, `phi_vy`, `theta`, or `both`.

`model.use_baseline_frequency_input`
: Adds the VIVANA-TD baseline frequency `fhat_td` as a network input.

`model.use_memory_std_inputs`
: Adds VIVANA-TD memory standard deviations to the network input.

`model.use_acceleration_input`
: Adds structural acceleration as a network input.

`vivana_td`
: Baseline VIVANA-TD parameters. Use `cv`, `cd`, `ca`, `fhat0`, `fhat_min`,
`fhat_max`, `n_memory`, `memory_mode`, `tau_over_tref`, and `memory_tau_s`.
The memory mode values are `fixed_n_memory`, `fixed_tau`, and `tau_over_tref`.

## Standalone Model

`standalone.latent_dim`
: Number of learned latent variables propagated during rollout.

`standalone.history_length`
: Number of previous timesteps used by the GRU encoder to infer the initial
latent state.

`standalone.history_include_acceleration`
: Includes acceleration in the encoder history window.

`standalone.latent_update_scheme`
: Currently `dt_scaled`; the network predicts a bounded latent-rate update.

## Constraints

`constraints.force_coefficient_bound`
: Tanh bound on force-coefficient output. For correction models this bounds
`Delta C_F`; for standalone models this bounds `C_F`.

`constraints.force_regularization_weight`, `constraints.force_regularization_norm`
: Weight and norm type for force-output regularization. Norm is `l1` or `l2`.

`constraints.frequency_regularization_weight`, `constraints.frequency_regularization_norm`
: Weight and norm type for frequency-correction regularization.

`constraints.frequency_bound_base_interval`
: Optional `[min, max]` interval for corrected `fhat`. `null` uses the VIVANA-TD
`fhat_min` and `fhat_max` values.

`constraints.frequency_bound_multiplier`
: Multiplier applied to the base frequency interval. A value of `1.0` gives the
strict baseline interval.

`constraints.debug_zero_correction_output`
: Debug option that zeros learned correction heads so validation reduces to the
uncorrected VIVANA-TD baseline.

## Architecture And Training

`architecture.backbone_type`
: Network backbone. Supported values are `pirate`, `residual`, and `mlp`.

`architecture.residual_kwargs`, `architecture.mlp_kwargs`, `architecture.pirate_kwargs`
: Backbone-specific hidden size, depth, activation, Fourier-feature, and related
settings.

`training.batch_size`, `training.epochs`, `training.max_grad_norm`
: Main optimization settings.

`training.output_init_mode`, `training.output_init_tiny_std`
: Final output-head initialization. Use `zero`, `tiny`, or `standard`.

`optim`
: Optimizer and learning-rate scheduler settings. Current configs use Adam with
the cosine scheduler.

## Losses

`loss.one_step_state_weight`
: Weight on the one-step state loss.

`loss.multi_step_state_weight`
: Weight on the pointwise multi-step rollout state loss.

`loss.rollout_horizon_steps`
: Multi-step rollout horizon `R`.

`loss.rollout_batch_size`
: Batch size for rollout-window losses. Set `0` to fall back to
`training.batch_size`.

`loss.multi_step_amplitude_weight`
: Weight on the multi-step displacement standard-deviation loss. When
`rollout_disp_mean_in_std_loss` is true, the displacement-mean offset term is
included under the same weight.

`loss.multi_step_frequency_weight`
: Weight on the configured frequency-domain multi-step loss.

`loss.multi_step_frequency_loss`
: `spectral_amplitude` compares displacement spectral amplitudes. `dominant_frequency`
compares a differentiable dominant-frequency estimate.

`loss.frequency_loss_peak_relative_bandwidth`
: Relative bandwidth around the reference dominant peak. `0.0` compares the full
non-DC spectrum.

`loss.frequency_loss_use_hann_window`
: Applies a Hann window before the differentiable FFT loss.

`loss.dominant_frequency_p`, `loss.dominant_frequency_peak_alpha`
: Exponent for the dominant-frequency error and peak-concentration exponent.

`loss.use_gradient_normalization`
: Enables anchored gradient normalization for active loss terms.

## Runtime Sections

`runtime`
: Device and dataloader worker settings.

`precision`
: TF32 and AMP settings.

`compile`
: Optional `torch.compile` settings.

`logging`
: Run directory, validation cadence, print cadence, and async validation settings.

## Backward Compatibility

Old names such as `data.reduce_time`, `model.correction_mode`,
`constraints.mean_reg`, and `loss.rollout_disp_spectral_loss` are still accepted.
If a config supplies both an old and a new name with conflicting values, parsing
raises a `ValueError`.
